# 2026-10-26 IOS XR の max-metric（起動時に OSPF のコストを最大にする）

## 今日学んだこと

- IOS XR で、電源を入れ直したときに **OSPF のコストを最大にする**設定（max-metric）
- これまでの検証メモから、**ループバックを広報するには、OSPF でループバックを指定する必要がある**らしいこと

## max-metric（起動時に OSPF のコストを最大にする）

### どんな設定か

ルータの電源を入れ直したとき、起動してからしばらくの間、自分が広報する Router LSA のリンクのコストを**最大値**にする設定。

```
router ospf 1
 max-metric router-lsa on-startup <秒数>
```

### なぜするのか

- 電源を入れると、**RP より先に LC が上がる**
- LC が上がるとリンクは上がるが、RP がまだ上がっていないので、**転送する能力がない**
- それでも OSPF 上は通れるように見えるので、フローがそのルータに流れてくる
- 結果として、そのルータが**トラフィックを吸い込んで捨てる**（吸い込みが発生する）
- コストを最大にしておけば、ほかのルータはそのルータを経由する経路を選ばない。起動が終わってからコストを元に戻す

!!! note "用語"
    - **RP**（Route Processor）：ルーティングプロトコルや経路計算を担当するカード
    - **LC**（Line Card）：インターフェースがあって、実際にパケットを転送するカード

### 検証できるか

→ [OSPF の max-metric（起動時にコストを最大にする）](../verification/ospf/max-metric-on-startup.md) に検証項目として入れた（検証前）。

## ループバックの広報

これまでの検証メモから、ループバックを OSPF で広報するには、**OSPF でループバックを指定する必要がある**みたい。

- IOSv の検証で、OSPF を有効にしていないループバックは広報されなかった（[OSPF で広報される経路](../verification/ospf/advertised-routes.md)）
- IOS XR の検証で、OSPF を有効にした IF のネットワークだけが Router LSA に入った（[物理 IF だけで有効にしたとき](../verification/ospf/physical-if-only.md)）

## 補足・アドバイス

!!! tip "自分で確かめてみよう"
    答えは書かず、考えるための手がかりと、やってみると良いことを書いています。

### max-metric の理由について

1. **起動の順番をもう一度確かめる**：「RP より先に LC が上がる」と書いたが、機種（シャーシ型か、1台で全部入りか）や OS によって起動の順番は違う。業務で扱っている機種のドキュメントやコンソールログで、RP と LC のどちらが先に上がるのか確かめてみよう
2. **「転送できない」のは RP の何が終わっていないからか**：max-metric は、ほかにも「IGP は上がったが、**BGP の経路がまだそろっていない**」「**LDP のラベル**がまだ配られていない」「**FIB（転送用の表）が LC に書き込まれていない**」ときの吸い込み対策としても説明されることが多い。`on-startup` のあとに付けられる `wait-for-bgp` というキーワードがある。これは何を待つためのものか、調べてみよう
3. **最大値はいくつか**：Router LSA のコストの最大値はいくつか。そのコストになったリンクは、「通れなくなる」のか「なるべく通らない」のか。迂回路がない場合はどうなるか考えてみよう
4. **どのリンクのコストが上がるのか**：Router LSA には「別のルータ」と「スタブネットワーク」のリンクがあった（[物理 IF の検証](../verification/ospf/physical-if-only.md)）。max-metric で最大になるのはどちらか。`include-stub` というキーワードを調べてみよう
5. **元になっている RFC**：この考え方は「OSPF Stub Router Advertisement」という RFC にある。RFC 番号を調べて、[OSPF のページ](../protocols/ospf/index.md) の RFC の表に足してみよう
6. **IS-IS では**：IS-IS にも同じ目的の設定（overload bit）がある。CCIE SP では IS-IS もよく使うので、あとで比べてみよう

### ループバックの広報について

7. **条件は1つだけか**：「ループバックだけで有効にしたとき」の検証では、ループバックを OSPF で指定していたのに、対向には広報されなかった。ループバックを OSPF で指定する以外に、もう1つ必要なことは何だったか。2つの検証の結果を並べて考えてみよう
8. **両方そろえて確かめる**：物理 IF（G0/0/0/0）とループバックの**両方**で OSPF を有効にして、対向の `show route ospf` にループバックが載るか確かめよう。載ったとき、プレフィックス長は /32 か、それ以外か。Router LSA の中では、ループバックはどの種類のリンクとして書かれるか、予想してから見てみよう
