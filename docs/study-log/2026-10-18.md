## 学んだこと

### デバッグコマンド

- `show` はその時点の**状態**（写真）、`debug` は今起きている**やり取り**（実況中継）を見るコマンド
- `show` で「何が起きているか」、`debug` で「なぜそうなっているか」を見る
- 使い終わったら必ず `undebug all`。CPU に負荷がかかるので、本番機器では慎重に使う

### MPLS L3VPN の経路の流れ

CE1 の経路が CE2 に届くまでの順番（詳しくは[検証メモ](../verification/l3vpn-ce-route-to-vrf.md)）。

1. CE1 → PE1：IGP / eBGP で IPv4 の経路を広告
2. PE1：VRF の経路表に入れる（この時点では RD も RT も付いていない）
3. PE1：MP-BGP に再配布し、RD を付けて VPNv4 にし、RT（export）を付ける
4. PE1 → PE2：iBGP で VPNv4 の経路を VPN ラベル・RT 付きで広告（P は BGP に参加しない）
5. PE2：RT（import）を見て取り込む VRF を決め、RD を外す
6. PE2：IPv4 の経路として VRF の経路表に入れる
7. PE2 → CE2：IGP / eBGP で IPv4 の経路を広告

最初は「CE から来た経路に RT import を付けて VRF に載せる」と考えていたが、**RT は自分の VRF に入れるときには使わない**。export は送り出すときに付けるもの、import は他の PE から受け取ったときにどの VRF に入れるかを決めるフィルタ。

### RD と RT と VPN ラベル

| | 役割 | パケットに付くか |
| --- | --- | --- |
| RD | アドレスが重なっても区別できるようにする目印。お客さまの識別には使えない（PE ごとに変えてもよい） | 付かない |
| RT | どの VRF に入れるかを決める荷札 | 付かない |
| VPN ラベル | 出口の PE で、どの VRF のパケットかを決める | 付く |

- RD と RT は経路をやり取りするとき（制御プレーン）だけの情報で、パケットには付かない
- パケットを正しいお客さまに届けるのは VPN ラベル。入口の PE は、入ってきたインターフェース（VRF）で表を引いてラベルを付け、出口の PE はラベルを見て VRF を決める

### VRF と VPNv4 の役割分担

- PE と PE の間では、全部のお客さまの経路が VPNv4 という1つのテーブルにまとめて入っている。P ルータには VRF の設定すらない
- それでも VRF が必要なのは、パケットには RD も RT も付いていないので、PE がお客さまごとに**表を分けて**転送する必要があるから
- 例えると、VPNv4 は荷札付きの荷物を混載するトラック、VRF は各家の郵便受け

### PE-PE は vpnv4、PE-CE は ipv4 vrf になる理由

| | PE-PE | PE-CE |
| --- | --- | --- |
| アドレスファミリー | vpnv4 | ipv4 vrf ○○（PE 側の書き方） |
| 回線を流れる経路 | RD:プレフィックス ＋ RT ＋ ラベル | 普通の IPv4 |
| 相手 | VPN を理解する PE | VPN を知らない CE |
| 経路の入れ先 | VPNv4 のテーブル | その VRF のテーブル |

`ipv4 vrf ○○` の vrf の名前は、送り方ではなく**入れ先**を決めている。

### BGP

詳しくは [BGP のページ](../protocols/bgp/index.md)にまとめた。

- `show ip bgp neighbors` で、ネイバーとやり取りできるケイパビリティ（アドレスファミリーなど）を確認できる
- ベストパスは決まった順番で属性を比べて1つ選ぶ。設計でよく使うのは Local Preference・AS_PATH の長さ・MED・ネクストホップまでの IGP コスト
- `maximum-paths` でマルチパスにできる。ネクストホップまでの IGP コストまでの属性がすべて同じである必要がある。ベストパスは1つのまま
