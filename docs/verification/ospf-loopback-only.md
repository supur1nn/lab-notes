## 問い

**IOS XR で、OSPF をループバックだけで有効にしたとき、ループバックのアドレスは対向のルータに広報されるのか。**

## 構成

CML-Personal（ベアメタル）上の IOS XRv 9000 2台。

```mermaid
graph LR
  D1["desktop-1"] -- "E1 ⇔ G0/1" --- X1["xr9kv-1"]
  X1 -- "G0/0 ⇔ G0/0" --- X0["xr9kv-0"]
  X1 -- "G0/2 ⇔ G0/2" --- X0
  X0 -- "G0/1 ⇔ E1" --- D0["desktop-0"]
```

| 機器 | インターフェース | IP アドレス |
| --- | --- | --- |
| xr9kv-1 ⇔ xr9kv-0 | G0/0/0/0 | 10.0.0.1/30 ⇔ 10.0.0.2/30 |
| xr9kv-1 ⇔ xr9kv-0 | G0/0/0/2 | 10.0.1.1/30 ⇔ 10.0.1.2/30 |
| xr9kv-1 / xr9kv-0 | Loopback0 | （ループバックのアドレスを書く） |

## 仮説

- OSPF の設定でループバックを有効にすれば、そのループバックのアドレスが対向のルータに広報されるのではないか

## 設定

OSPF は**ループバックだけ**で有効にした。XR 同士をつなぐ物理インターフェース（G0/0/0/0、G0/0/0/2）は、OSPF に入れていない。

```
router ospf 1
 area 0
  interface Loopback0
  !
 !
!
commit
```

（実際に入れた設定をここに貼る）

## 確認

| どこで | コマンド | 何を見るか |
| --- | --- | --- |
| 両方 | `show ospf interface brief` | OSPF が有効になっているインターフェース |
| 両方 | `show ospf neighbor` | 対向とネイバーになっているか |
| 両方 | `show route ospf` | 対向のループバックが OSPF の経路（`O`）として載っているか |
| 両方 | `show ospf database` | どんな LSA を持っているか |

（確認コマンドの出力をここに貼る）

## 結果

- **対向のルータに、ループバックのアドレスは広報されなかった**
- 仮説は外れた
